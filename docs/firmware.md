# 固件复现与排查

## 环境与模块

在取得相应版本的 VeriHealthi Embedded SDK v3.8 和团队集成文件后，用 Nuclei Studio 导入 `vesc` 工程，选择 Release 构建。检查编译、链接和 post-build 打包日志。打包正常时，输出目录包含 `vesc.img` 和 `vesc_combine.img`。按板卡所用 Bootloader 和官方烧录流程选择镜像。烧录后用串口查看启动日志，再连接 VeriHealthi App。

| SDK 侧模块 | 责任 |
|---|---|
| `main.c` | 保留 SDK 初始化入口 |
| `vesc_sensor.c` | IMU 初始化、FIFO 读取和样本环形缓冲 |
| `vesc_algorithm.c`、`vesc_gesture.c` | 步态逻辑、手势识别及事件输出 |
| `vesc_app.c` | 任务组织、BLE 服务、校时、穿戴与看门狗集成 |
| `vesc_protocol.c`、`vesc_raw.c` | 结果序列化、CRC-8 和 RAW 路径 |

## 联调清单

1. **确认采集。** 动开发板并观察串口轴值与采样计数。接近 50 样本/秒且轴值随姿态变化，可先确认 IMU 传感器到采集任务的链路。
2. **验证 RAW 控制。** 在 App 发出开启命令后，核对控制特征值回读是否为开启状态。接着查看 RAW 订阅、通知发送返回值和 App 的 RAW 页面。
3. **验证结果上报。** 执行已知动作，按顺序对照算法结果日志、BLE 通知日志、App 实时记录。保存同一事件序号，便于跨环节核对。
4. **验证断连行为。** 先完成校时，再断连并做已知动作，重连后核对序号与原始事件时间戳。测试有限缓存的容量边界时，同时检查串口溢出日志。
5. **验证时间。** 多次读回设备 UTC 并记录手机侧请求发出、响应接收时间。用两者中点估算偏差，用往返时间标记本次测量的不确定性。测手势端到端延迟时，分别记录动作发生、算法输出和手机收到的时刻。
6. **验证看门狗。** 在授权测试板上确认故障注入请求进入设备处理函数，再检查喂狗是否停止、板子是否复位，以及重连后的功能是否恢复。App 的「请求已发送」提示只能验证手机端发起了操作。

## 结果帧

结果帧以 ASCII `vesc` 开头，接着是 1 字节标志、1 字节负载 CRC-8、1 字节记录数和 2 字节小端负载长度。每条记录由 8 字节 UTC 毫秒时间戳、2 字节序号、1 字节动作码组成。CRC-8/SMBUS 检查范围为负载，参数为多项式 `0x07`、初值 `0x00`、无反射、输出异或 `0x00`。

可把 BLE 抓包中的结果特征值复制成一段十六进制字符串传给检查器。CRC 可用于检测负载损坏。丢包和漏记应结合记录序号检查。
